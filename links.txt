........................................

1. Verificar a branch atual:

git branch --show-current

2. Verificar os arquivos modificados:

git status

3. Adicionar as alterações:

git add .

4. Conferir os arquivos preparados:

git diff --cached --name-status

5. Registrar as alterações:

git commit -m "Atualização dos materiais do Portal Engenharia UESC"

git push origin main

7. Confirmar a atualização:

git status

ATUALIZAÇÃO DO GITHUB

Procedimento para atualizar o repositório após modificações locais.

==================================================
1. VERIFICAR A BRANCH ATUAL
==================================================

git branch --show-current

Mostra a branch em que estamos trabalhando.

Para publicar diretamente na branch principal, o resultado deve ser:

main

Se aparecer outra branch, verificar antes de continuar.


==================================================
2. VERIFICAR O STATUS DO REPOSITÓRIO
==================================================

git status

Mostra quais arquivos foram modificados, adicionados ou removidos.

Verificar se existem arquivos temporários que não devem ser publicados.


==================================================
3. ADICIONAR OS ARQUIVOS AO PRÓXIMO COMMIT
==================================================

git add .

Adiciona arquivos novos, modificados e excluídos do diretório atual e suas subpastas.

Para conferir quais alterações foram preparadas:

git diff --cached --name-status

ATENÇÃO: Evitar incluir arquivos temporários, como .ipynb_checkpoints, ou configurações locais desnecessárias.


==================================================
4. CRIAR UM COMMIT
==================================================

git commit -m "Correção dos caminhos das imagens nos notebooks Python"

Outros exemplos:

git commit -m "Atualização dos materiais didáticos da CET001"

git commit -m "Reorganização das páginas HTML do Portal Engenharia UESC"

Utilizar mensagens que descrevam as alterações. O Git registra automaticamente a data e o horário.


==================================================
5. ENVIAR AS ALTERAÇÕES AO GITHUB
==================================================

git push origin main

Envia os commits locais para a branch main do repositório remoto.

ATENÇÃO: Confirmar que estamos trabalhando na branch main antes de executar esse comando.


==================================================
6. CONFIRMAR A ATUALIZAÇÃO
==================================================

git status

Quando não houver alterações pendentes e a branch estiver sincronizada, o Git poderá apresentar:

On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

Também é recomendável verificar os arquivos diretamente no GitHub.


==================================================
PROCEDIMENTO ALTERNATIVO — GITHUB DESKTOP
==================================================

1. Abrir o GitHub Desktop.

2. Confirmar:
   Current repository: portal-engenharia-uesc
   Current branch: main

3. Na aba Changes, verificar os arquivos modificados, adicionados ou excluídos.

4. Selecionar somente os arquivos que devem entrar no commit.

5. No campo Summary (required), escrever uma mensagem, por exemplo:

   Correção dos caminhos das imagens nos notebooks Python

6. Clicar em Commit to main.

7. Clicar em Push origin.

8. Aguardar o botão superior voltar a mostrar Fetch origin.

9. Verificar se aparece 0 changed files.

10. Conferir no GitHub se os arquivos foram publicados corretamente.


==================================================
OBSERVAÇÕES IMPORTANTES
==================================================

git add .  -> Prepara as alterações para o commit.

git commit -> Registra as alterações no histórico local.

git push   -> Envia os commits para o GitHub.

A branch main deve conter a versão principal do projeto.

Alterações maiores podem ser desenvolvidas em uma branch separada e depois incorporadas à main.

Evitar publicar arquivos temporários, especialmente os diretórios .ipynb_checkpoints.

Não é necessário utilizar o terminal quando as operações já foram realizadas pelo GitHub Desktop.

Para o Portal Engenharia UESC, recomenda-se utilizar o GitHub Desktop nas atualizações rotineiras e manter estes comandos como referência.
